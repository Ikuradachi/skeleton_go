01 / FOUNDATIONS

Small core.
Defaults you can test.

Defaults cover the common path. Add complexity when a feature needs it.

01

Boot with no setup

Config files and databases are optional. Built-in defaults run the API and local landing page.

02

Clean lifecycle

SIGINT and SIGTERM trigger graceful shutdown. A startup failure stops the process immediately.

03

Operations in view

Liveness, readiness, request IDs, latency, status, and response size are logged from the first request.

04

Bounded by default

Server timeouts, panic recovery, a 2 MiB body limit, read-only CORS, CSP, and security headers are active.

02 / STRUCTURE

See the request path at a glance.

The composition root lives in cmd. HTTP transport and private feature code stay under internal; small reusable infrastructure packages live in pkg.

Request path

  1. 01
    Middleware

    Request ID, limits, security, logging, recovery.

  2. 02
    Router

    Maps HTTP intent to a feature handler.

  3. 03
    Feature

    Owns the smallest contract and dependency set it needs.

  4. 04
    Response

    Returns consistent JSON or static assets from app.

04 / QUICK START

Run the first request.

Requires Go 1.26+. MySQL is optional; no env file or generator is needed.

STEP 1

Clone and run

git clone https://github.com/Ikuradachi/skeleton_go.git
cd skeleton_go
go run ./cmd/api
STEP 2

Verify

curl http://localhost:38600/health/ready
OPTIONAL

Docker

docker compose up --build

DATABASE / OPT-IN

Enable it when a feature needs it.

Copy the example config, then set db.driver and db.dsn. The readiness probe will start checking the connection.

cp pkg/config/config.yaml.example pkg/config/config.yaml
